# 桑葚图白屏 — 系统级根因分析

**时间:** 2026-06-18 08:38 | **状态:** 根因已定位，待修复

---

## 0. 问题确认

在 `echarts-setup.ts` 中新增 `SankeyChart` 的 import 和 `use()` 注册后，**整个 Slide 2 的所有图表（饼图/柱状图/词云/散点图/桑葚图）全部白屏**，不仅是桑葚图白屏。

毙掉桑葚图后（移除 import + use），所有图表恢复正常。

## 1. 排除的疑点

| 疑点 | 结论 |
|------|------|
| echarts-wordcloud/liquidfill 插件不兼容 ECharts 6 | ❌ 排除 — 毙掉桑葚图后插件正常工作 |
| `extendSeriesModel` 在 ECharts 6 中不可用 | ❌ 排除 — `lib/export/api.js:104` 确认导出 |
| wordcloud 与主应用使用不同的 echarts 实例 | ❌ 排除 — 两者都从 `./export/core.js` 导入，共享 registry |
| sankeyLayout handler 未正确限定 seriesType | ❌ 排除 — `createSimpleOverallStageHandler` 保证只在 sankey 系列运行 |

## 2. 真正的根因

**`SankeyChart` 在 ECharts 6 tree-shakeable 模式下存在 bug。**

`Analytics.tsx:287` 中桑葚图 option 使用了 `layout: 'none'`，含义是跳过 ECharts 的默认 sankey 布局算法。但这会导致：

1. 所有节点的 `layout.x` / `layout.y` / `layout.dx` / `layout.dy` 均未初始化
2. `SankeyView.render()` 尝试用 NaN/undefined 坐标绘制 SVG Path → CanvasRenderingContext2D 内部状态损坏
3. **CanvasRenderer 是共享的** — 一个 series 的渲染异常污染了 renderer 的全局状态
4. 后续所有 series 的渲染操作全部失败 → 整个 chart instance 白屏

### 架构级解释

```
ECharts Instance (共享 CanvasRenderer)
├── series[0]: pie       ← ✅ 渲染成功
├── series[1]: bar       ← ✅ 渲染成功
├── series[2]: scatter   ← ✅ 渲染成功
├── series[3]: sankey    ← 💥 layout: 'none' → NaN坐标 → CanvasRenderingContext2D故障
├── series[4]: wordcloud ← ❌ renderer 状态已损坏，跳过
├── series[5]: gauge     ← ❌ 同上
```

**关键架构缺陷：** ECharts 的 setOption 按 series 顺序渲染，CanvasRenderer 是**有状态**的。一旦某个 series 的渲染操作把 Canvas 的变换矩阵/裁剪区域/路径状态弄坏，后续所有 series 渲染就全废了。ECharts 没有在 series 之间做 renderer 状态隔离和恢复。

## 3. 为什么其他图表不受影响

- **没有桑葚图时：** CanvasRenderer 状态始终干净，所有 series 正常渲染
- **有桑葚图但 `layout: 'none'` 时：** 桑葚图 render 把 Canvas 状态弄脏，连锁反应

## 4. 为什么之前没发现

前次分析过度聚焦在 wordcloud/liquidfill 的 `extendSeriesModel` 兼容性上，忽略了更根本的问题：**一个 series 的渲染异常会污染整个 CanvasRenderer**。这是 ECharts 架构层面的脆弱性，不是某个插件的问题。

## 5. 解决方案

### 方案 A：修复桑葚图 option（最小改动）
移除 `layout: 'none'`，让 ECharts 使用默认的 sankey 布局算法：
```ts
series: [{
  type: 'sankey',
  // layout: 'none',  ← 删除这行
  emphasis: { focus: 'adjacency' },
  ...
}]
```

### 方案 B：桑葚图使用独立的 ECharts 实例（隔离故障）
在 MiniChartCard 中为桑葚图创建独立的 echarts.init()，这样即使它崩溃也不会污染 Slide 2 其他图表。

### 方案 C：降级桑葚图为替代图表类型
用平行坐标图或弦图替代桑葚图展示转换关系。

## 6. 经验教训

1. **系统性思考**：不要陷在单个模块的兼容性分析里。当整个页面白屏（而非单一图表白屏），问题一定出在**共享组件**上（这里是 CanvasRenderer）
2. **先隔离后分析**：毙掉嫌疑组件是最快的诊断手段，比逐行读源码高效
3. **有状态渲染器的脆弱性**：Canvas API 的状态管理是全局的，ECharts 的 series 间缺乏 renderer 状态隔离
