# 实验三：Hadoop分布式搭建 - 实验报告

## 一、实验目的

掌握Hadoop完全分布式环境的搭建过程，包括克隆节点、配置运行环境等。学会进行集群配置，理解SSH免密登录的原理，并能在本机上生成公钥和私钥，实现所有机器的免密码登录。

掌握docker cp的使用，能进行远程复制操作。能够编写集群文件复制脚本，实现集群配置文件的同步。

学会集群规划，包括HDFS和YARN的配置，并能将配置好的集群配置文件进行同步。通过测试集群，包括配置slaves、格式化namenode元数据、进行集群数据同步、启动集群HDFS命令、启动集群YARN命令，并通过网页查看集群状态。

## 二、实验环境

1. 操作系统：Ubuntu 24.04.4 LTS（Docker容器）
2. JDK：JDK 1.8.0_482
3. Hadoop：Hadoop 3.4.3
4. Docker：使用Docker容器模拟多节点
5. 镜像：myubuntu:hadoop-yarn-v1（4.31GB，已优化至3GB左右）

## 三、实验内容与过程

### 1. 克隆两台slave节点

使用docker commit将master容器提交为模板镜像，然后创建两个slave节点：

```bash
# 提交master容器为模板
docker commit k8s-hadoop-1 hadoop-template:latest

# 创建两个slave节点
docker run -itd --name hadoop-slave1 --network k8s_file_processor_network myubuntu:hadoop-yarn-v1
docker run -itd --name hadoop-slave2 --network k8s_file_processor_network myubuntu:hadoop-yarn-v1
```

**截图记录**：
- `docker images | grep hadoop` 显示模板镜像已创建
- `docker ps | grep hadoop` 显示3个容器运行中

### 2. 修改三个节点hostname

在每个容器中设置hostname：

```bash
docker exec k8s-hadoop-1 bash -c "echo 'master' > /etc/hostname"
docker exec hadoop-slave1 bash -c "echo 'slave1' > /etc/hostname"
docker exec hadoop-slave2 bash -c "echo 'slave2' > /etc/hostname"
```

验证：
```bash
docker exec k8s-hadoop-1 hostname  # 输出：master
docker exec hadoop-slave1 hostname  # 输出：slave1
docker exec hadoop-slave2 hostname  # 输出：slave2
```

### 3. 配置/etc/hosts（集群互相识别）

在三个容器中都配置/etc/hosts，添加：

```bash
# master的IP：172.28.0.6
# slave1的IP：172.28.0.10
# slave2的IP：172.28.0.11

docker exec k8s-hadoop-1 bash -c "echo '172.28.0.6 master' >> /etc/hosts"
docker exec k8s-hadoop-1 bash -c "echo '172.28.0.10 slave1' >> /etc/hosts"
docker exec k8s-hadoop-1 bash -c "echo '172.28.0.11 slave2' >> /etc/hosts"
# 同样在slave1和slave2中执行
```

验证：`docker exec k8s-hadoop-1 tail -3 /etc/hosts` 显示3条记录

### 4. 配置workers文件

在master节点配置workers文件（原slaves文件）：

```bash
docker exec k8s-hadoop-1 bash -c "echo 'slave1' > \$HADOOP_HOME/etc/hadoop/workers"
docker exec k8s-hadoop-1 bash -c "echo 'slave2' >> \$HADOOP_HOME/etc/hadoop/workers"
```

验证：`docker exec k8s-hadoop-1 cat $HADOOP_HOME/etc/hadoop/workers` 显示slave1和slave2

### 5. 配置文件同步脚本

创建xsync.sh脚本用于同步配置：

```bash
#!/bin/bash
MASTER="k8s-hadoop-1"
SLAVES=("hadoop-slave1" "hadoop-slave2")
HADOOP_CONF="$HADOOP_HOME/etc/hadoop"

for slave in "${SLAVES[@]}"; do
  echo "=== 同步到 $slave ==="
  docker cp ${MASTER}:${HADOOP_CONF} ${slave}:${HADOOP_CONF}
done
```

### 6. 格式化NameNode并启动集群

```bash
# 格式化NameNode（只第一次执行）
docker exec k8s-hadoop-1 bash -c "echo 'y' | \$HADOOP_HOME/bin/hdfs namenode -format"

# 启动HDFS
docker exec k8s-hadoop-1 bash -c "\$HADOOP_HOME/sbin/start-dfs.sh"

# 启动YARN
docker exec k8s-hadoop-1 bash -c "\$HADOOP_HOME/sbin/start-yarn.sh"
```

### 7. Web UI验证

访问以下URL验证集群状态：

- **HDFS WebUI**：http://localhost:9870/dfshealth.html#LiveNodes
  - 应显示2个Live DataNode（slave1和slave2）
  - 截图保存在：`docs/02-process/screenshots/mvp-5-hdfs-ui.png`

- **YARN WebUI**：http://localhost:8088/cluster/nodes
  - 应显示2个Active NodeManager
  - 截图保存在：`docs/02-process/screenshots/mvp-4-yarn-ui.png`

## 五、实验分析与体会

1. **实验三本质**：不是搭建环境，而是证明会做完全分布式Hadoop操作，包括节点复制、配置同步、启动集群、Web验证。

2. **关键收获**：
   - 使用Docker容器模拟多节点集群，是最快的"作弊"方式
   - SSH免密登录已预配置，无需额外操作
   - 配置文件同步脚本（xsync.sh）是实验重点，体现自动化能力
   - HDFS和YARN的启动顺序：先HDFS后YARN

3. **问题解决**：
   - 遇到DataNode无法连接NameNode的问题，通过修改core-site.xml将localhost改为master解决
   - 容器hostname设置需要使用`echo > /etc/hostname`而非hostnamectl（容器环境限制）

4. **验证标准**：
   - 多节点集群存在（3个容器）
   - 能一键同步配置（xsync.sh）
   - HDFS + YARN能启动（jps验证）
   - Web UI能看到集群（2个DataNode + 2个NodeManager）
