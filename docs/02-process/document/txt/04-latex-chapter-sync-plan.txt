# LaTeX 章节同步计划

## 模板来源

`00-course-template-textified.txt` 已从 `docs/01-resources/课程大作业说明书-模板.docx` 抽取。后续章节写作以该文本为格式依据，以当前 CulCloud 系统为内容依据。

## LaTeX 章节映射

课程模板正文示例采用 7 章结构：绪论、相关软件及技术简介、系统分析、系统总体设计、系统详细设计及实现、系统测试、总结与展望。当前 LaTeX 已经具备 6 个正文文件，但 `chap03` 合并了承担“系统分析”和“总体设计”两章的内容。后续建议拆分为 7 章，便于把需求分析、架构设计、实现细节和测试结果分开写足，也避免截图和表格堆在少量文字里。

| LaTeX 文件 | 章节主题 | 内容来源 |
| --- | --- | --- |
| `data/chap01.tex` | 绪论 | 政策背景、竞品问题、课程项目目标 |
| `data/chap02.tex` | 相关技术与竞品分析 | Hadoop/Spark/FastAPI/React/MinIO/PDF.js 思路 |
| `data/chap03.tex` | 系统分析 | 用户角色、业务流程、功能性需求、非功能性需求、数据合规需求 |
| `data/chap04.tex` | 系统总体设计 | 总体架构、功能模块、数据流、部署结构、对象存储结构 |
| `data/chap05.tex` | 系统详细设计及实现 | 前端四模块、后端 API、转换服务、预览服务、PDF Studio、遥测分析 |
| `data/chap06.tex` | 系统测试 | 功能测试、接口测试、转换链路测试、UI 截图、性能与可用性指标 |
| `data/chap07.tex` | 总结与展望 | 已完成能力、限制、后续 PDF 真写回与多格式增强 |

## 字数与图表密度控制

后续写作使用 `docs/02-process/scripts/latex_chapter_audit.py` 计数。目标按中文字符粗估，不把表格内容和代码清单当作正文主要字数：

| 章节 | 目标中文字符数 | 图表建议 |
| --- | ---: | --- |
| 摘要 | 350--450 | 0 |
| 第 1 章 绪论 | 1400--1800 | 0--2 |
| 第 2 章 相关技术与调研 | 1600--2200 | 1--2 |
| 第 3 章 系统分析 | 1800--2400 | 2--3 |
| 第 4 章 系统总体设计 | 1800--2600 | 2--4 |
| 第 5 章 系统详细设计及实现 | 2600--3600 | 4--6 |
| 第 6 章 系统测试 | 1800--2600 | 3--5 |
| 第 7 章 总结与展望 | 900--1300 | 0--1 |

每张图或表附近至少要有 180--250 个中文字符解释其输入、输出、关键字段和结论；实现章节的截图组按每组 450 个中文字符以上补齐。正文必须显式引用图表，例如“如图 4-2 所示”“如表 5-1 所示”，避免图表成为孤立装饰。
