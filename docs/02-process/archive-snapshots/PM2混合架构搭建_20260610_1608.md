# 混合架构 PM2 + Docker Compose 治理体系确立

## 目的

完成 CulCloud 课程设计平台的 PM2 + Docker Compose 混合开发/演示架构搭建，确保全栈可一键启动。

## 架构定论

```
PM2 (应用层 - 本地热重载)
├── flask-analytics      :5050   数据分析 API (Python Flask)
└── culcloud-frontend-dev :5173  Vite 开发服务器

Docker Compose (基础设施层 - 容器化)
├── redis     :6379  任务队列/缓存
├── minio     :9010  S3 对象存储
├── gotenberg :3000  文档格式转换
└── api       :8000  FastAPI 文件处理后端
```

## 关键决策

1. **分层治理**：有状态/资源隔离的服务（Redis、MinIO、Gotenberg、FastAPI）用 Docker Compose；频繁改动的应用层（Flask 分析 API、前端 Vite）用 PM2 本地进程，获得热重载和快速迭代
2. **PM2 npm 问题**：QClaw 环境中的 `npm` 是 bash shell 脚本（`#!/usr/bin/env bash`），PM2 无法 fork 解析。解决方案：前端直接使用 `node_modules/.bin/vite`（Node.js 脚本），替代 `npm run dev`
3. **PM2 版本同步**：运行 `pm2 update` 将内存中的 PM2 守护进程从 v6.0.14 升级到 v7.0.1，解决重启时的状态不一致问题

## 启动脚本

- `scripts/stack-up.sh`：一键启动 Docker Compose 核心服务 + PM2 应用
- `scripts/demo-up.sh`：原有的按 profile 启动脚本（core/full/hadoop/analytics/all）
- `scripts/stack-down.sh`：停止 PM2 进程 + Docker 服务
