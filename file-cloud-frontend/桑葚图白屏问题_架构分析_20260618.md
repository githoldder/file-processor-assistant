## 2. 开源社区调研结果

### 2.1 🔑 关键发现: echarts-wordcloud#182

**Issue:** [ecomfe/echarts-wordcloud#182](https://github.com/ecomfe/echarts-wordcloud/issues/182)
**症状:** `TypeError: Cannot read properties of undefined (reading 'extendSeriesModel')` — 词云不渲染
**根因:** 项目中存在多个 echarts 实例（版本不一致），wordcloud UMD bundle 的 `require('echarts')` 解析到了不同的 echarts 实例
**修复:** 在 `package.json` 中使用 `overrides` 统一所有 echarts 版本为 5.4.0

### 2.2 🔑 当前项目的类似问题（更隐蔽）

**已验证:** `npm ls echarts` 显示所有依赖都被 deduped 到 `echarts@6.1.0`，不存在版本不一致。

**但存在更深层的问题：**

| 模块 | 入口点 | 注册方式 |
|------|--------|----------|
| `echarts-setup.ts` | `import * as echarts from 'echarts/core'` | `echarts.use(SankeyChart)` |
| `echarts-wordcloud` (UMD) | `require('echarts/lib/echarts')` | `echarts.extendSeriesModel(...)` |
| `echarts-liquidfill` (UMD) | `require('echarts/lib/echarts')` | `echarts.extendSeriesModel(...)` |

**冲突机制:**
- `echarts/core` → 解析到 `node_modules/echarts/core.js`
- `echarts/lib/echarts` → 解析到 `node_modules/echarts/lib/echarts.js`
- 在 ECharts 6 tree-shakeable 架构中，`echarts/core` 和 `echarts/lib/echarts` 导入不同的内部模块
- 虽然它们共享 import chain → 相同 echarts 单例，但 **wordcloud/liquidfill 可能在 echarts.use() 调用前就执行了 `extendSeriesModel`**
- 如果 wordcloud 的 imports 先执行，它会读取到一个还未注册基础 series model 的 echarts，导致 `Cannot read properties of undefined`
