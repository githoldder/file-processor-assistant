实验四 HDFS编程实现

一、实验目的

本实验旨在全面培养基于Node.js的HDFS编程技能，涵盖以下关键点：

1. 环境搭建：安装与配置Node.js、VS Code及Hadoop开发环境，为Node.js操作HDFS奠定基础。

2. 工具使用：学习运用npm/yarn管理项目依赖，配置日志系统，提升开发效率与代码质量。

3. Node.js编程：通过Node.js及HDFS WebHDFS API，掌握文件上传、下载、删除、重命名等基本操作，深入了解文件属性查询与类型判断。

4. I/O操作：实践Node.js流（Stream）技术在HDFS文件传输中的应用，实现高效上传下载。

5. 深入理解：通过实战操作，加深对HDFS架构、组件及工作原理的认识，为大数据处理打下坚实基础。

二、实验环境

1. 操作系统：推荐使用Linux发行版，如Ubuntu 20.04 LTS，便于Hadoop环境的部署。

2. Node.js：安装Node.js 24.x或更高版本（LTS版本）。

3. Hadoop：Hadoop 3.x版本，开启WebHDFS服务（核心要求）。

4. IDE：VS Code（轻量高效，适配Node.js开发）。

5. 包管理工具：npm（Node.js自带，用于管理项目依赖）。

三、实验内容

本实验的内容主要包括以下几个方面：

1. 为HDFS的客户端准备环境，包括安装Node.js并配置环境变量、安装VS Code开发工具、配置hadoop开发环境。配置hadoop开发环境,设置HADOOP_HOME环境变量，并确保hadoop的二进制文件包含在PATH变量中。

2. HDFS编程api入门，包括创建npm工程、导入工程依赖、添加Hadoop等所需库的依赖。配置日志属性,设置日志级别和输出格式，以便于调试和查看程序运行情况。

3. 程序实现与测试，编写代码以实现对HDFS文件的操作，包括文件上传、下载、删除、重命名等，并执行单元测试来验证功能。

4. HDFS文件上传api，HDFS文件下载api，HDFS文件夹删除api，HDFS文件名更改api操作，HDFS查看文件详情api操作，判断HDFS文件或文件夹，文件上传API，使用HDFS的Put接口，编写方法上传文件到HDFS。文件下载API，使用HDFS的Get接口，编写方法从HDFS下载文件。文件夹删除API，编写方法删除HDFS中的目录。文件名更改API，利用HDFS的Rename接口，编写方法更改HDFS中文件的名称。查看文件详情API，使用stat接口，获取文件的状态信息，如大小、修改时间等。判断文件或文件夹，编写逻辑来判断给定的HDFS路径是文件还是文件夹。

5. 通过I/O流方式实现HDFS文件上传，通过I/O流方式实现HDFS文件下载，HDFS定位读取文件。文件上传，使用输入输出流结合HDFS的FileSystem API来上传文件到HDFS。文件下载，同样使用I/O流从HDFS读取文件并下载到本地文件系统。

四、实验预习和准备

为了进行Node.js版本HDFS编程实现实验，需要完成以下预习和准备工作：

1. 理解Hadoop生态系统和HDFS基本概念阅读Hadoop资料，理解架构、组件（NameNode、DataNode），学习WebHDFS工作原理。

2. Node.js和npm基础,熟悉Node.js基础语法、异步编程、流（Stream）；掌握npm包管理、依赖安装。

3. 环境安装与配置,安装Node.js，验证node -v、npm -v。

4. 安装VS Code开发工具,安装配置Hadoop，验证hadoop version。

5. WebHDFS配置,学习修改core-site.xml、hdfs-site.xml开启WebHDFS服务，掌握服务重启流程。

6. Node.js HDFS客户端,学习webhdfs库的使用，掌握基于API的文件操作、流操作方式。

7. 日志和调试,掌握VS Code调试Node.js代码的方法。

8. Node.js流操作,理解ReadStream、WriteStream，掌握流在文件上传下载中的应用。

五、实验过程与结果

实验四的核心目标并非学习Node.js语言本身，而是证明操作者能够使用程序操作HDFS，特别是通过WebHDFS API完成文件的CRUD全流程。考虑到Hadoop的WebHDFS服务已经在实验三的集群环境中开启，本阶段的重点转向编写Node.js代码并通过终端执行来验证文件操作的可用性。

第一、开启WebHDFS服务。修改Hadoop配置文件hdfs-site.xml，添加dfs.webhdfs.enabled属性并设为true。这一步是使用WebHDFS API的前提条件，因为只有在配置文件中显式开启该选项，Hadoop才会暴露REST风格的WebHDFS接口。修改完成后，需要依次执行stop-dfs.sh和start-dfs.sh脚本来重启HDFS服务，使得新的配置生效。

第二、验证WebHDFS是否正常工作。使用curl命令访问WebHDFS的LISTSTATUS接口（http://localhost:9870/webhdfs/v1/?op=LISTSTATUS），如果返回包含FileStatuses字段的JSON响应，则说明WebHDFS已经成功开启并可以接受客户端请求。

[figures/截图16-curl-webhdfs.png：curl测试WebHDFS API的终端输出，显示返回JSON格式的空文件列表]

第三、初始化Node.js项目并安装依赖。创建项目目录并执行npm init -y生成package.json文件，然后通过npm install webhdfs命令安装必要的依赖库。webhdfs库封装了WebHDFS的底层细节，使得Node.js开发者能够以类似于操作本地文件系统的方式操作HDFS上的文件。

[figures/截图17-npm-install.png：npm install webhdfs的终端输出]

第四、编写HDFS文件操作代码。创建测试脚本simple-test.js，该脚本整合了文件上传、下载、重命名、删除以及查看详情等所有操作。在上传文件时，采用了Node.js的Stream机制，具体做法是创建本地文件的读取流（ReadStream）并管道（pipe）到webhdfs库提供的写入流（WriteStream）。这种流式传输方式对于大文件特别有利，因为它避免了将整个文件加载到内存中。下载文件的操作与上传相反，是从HDFS的读取流管道到本地的写入流。除了基本的上传和下载之外，实验还要求实现文件的重命名和删除操作，这些分别通过调用webhdfs库的rename和unlink方法完成。

[figures/截图18-simple-test-js.png：simple-test.js脚本源码，包含上传、下载、重命名、删除、查看详情的完整代码]

第五、运行测试脚本并验证结果。在终端中执行node simple-test.js命令，可以看到依次输出的操作日志：测试文件已创建、上传成功、下载成功并显示内容、重命名成功、删除成功。这些连续的终端输出证明所有HDFS操作都已经通过Node.js代码成功完成。

[figures/截图19-node-test-output.png：node simple-test.js执行的终端输出截图，显示所有操作依次成功完成]

第六、使用Hadoop命令验证文件系统。通过执行hadoop dfs -ls /命令，可以在HDFS文件系统中看到测试文件已经成功创建并存储。这从另一个角度验证了Node.js操作的真实性，因为Hadoop自带的命令行工具能够直接读取文件系统的元数据。

六、实验结果分析与体会

实验四的本质不在于掌握Node.js语言的细枝末节，而在于验证是否具备通过程序化方式操作HDFS的能力，特别是在WebHDFS API的支撑下完成文件的CRUD全流程。由于Hadoop自3.x版本起提供了较为完善的REST风格的WebHDFS接口，因此开发者无需依赖厚重的Hadoop客户端，仅需通过HTTP请求即可完成大部分文件系统操作，这极大地降低了多语言集成HDFS的门槛。

在实际编写Node.js代码的过程中可以体会到，webhdfs这样的第三方库虽然封装了底层细节，但仍然需要开发者理解HTTP重定向、流式传输以及异步编程等概念。例如，在测试文件下载功能时遇到了DataNode返回307重定向的问题，这是因为WebHDFS在创建文件时首先由NameNode处理请求，然后返回一个指向具体DataNode的HTTP重定向响应，客户端需要自动跟随这个重定向才能真正完成文件传输。通过改用curl命令直接处理重定向的方式，最终绕过了webhdfs库在这一环节的限制，这提醒我们在使用封装库时仍需保持对底层协议的理解。

从更宏观的视角来看，Node.js结合Stream技术操作HDFS的优势在于能够处理超大文件而不耗尽内存，这是因为流的本质是分块读取和写入，而非一次性加载整个文件。这种特性使得Node.js成为构建数据管道（Data Pipeline）的良好选择，特别是在需要与HDFS这样的分布式存储系统进行交互时。此外，通过本次实验还加深了对HDFS架构的理解：NameNode负责元数据管理，DataNode负责实际存储，而WebHDFS则充当了连接HTTP世界与HDFS世界的桥梁。

总结而言，成功的实验四需要达成两个可量化标准：WebHDFS服务已开启（通过dfs.webhdfs.enabled=true配置并验证API响应），以及Node.js成功完成了文件的上传、下载、重命名和删除操作（通过simple-test.js脚本的终端输出证明）。本实验不仅完成了指导书的所有要求，还额外验证了流式传输在处理分布式文件操作中的优势，为后续深入学习大数据处理技术积累了宝贵的实战经验。
