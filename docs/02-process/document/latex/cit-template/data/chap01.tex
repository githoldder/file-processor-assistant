\chapter{绪论}

本章围绕 CulCloud 云盘与大数据分析平台的选题来源展开，说明课程资料管理、文件转换、PDF 批注和实验数据追踪中的现实问题，并给出本文的主要工作与章节安排。

\section{课题背景}

\subsection{课程资料管理需求}

随着课程资料、实验截图、数据集、报告文档和演示材料不断增长，学生在完成大数据与云计算课程项目时经常需要在本地文件、云端文件、格式转换工具和 PDF 标注工具之间反复切换。传统处理方式存在上传入口分散、文件分类不清晰、预览空间不足和版本难以追踪等问题。

\subsection{文件处理与预览需求}

课程项目中的材料类型较多，常见文件包括 PDF、Word、Excel、CSV、Markdown、文本、图片、压缩包以及演示文稿。若系统只能完成简单上传下载，用户仍需要依赖外部工具完成格式转换、内容预览和资料整理，无法形成稳定的课程工作流。

\subsection{实验数据追踪需求}

大数据与云计算课程不仅关注系统是否可用，也关注系统是否能够产生可分析的数据。CulCloud 将上传、预览、转换、下载、失败任务和日志记录纳入实验链路，为后续 Spark 聚合分析和管理驾驶舱展示提供数据基础。

\section{课题意义}

\subsection{提升课程文件处理效率}

本课题面向学生端提供可用的云盘与文件处理工作流，提高课程文档整理、转换和预览效率。用户可以在同一系统内完成上传、分类、预览、转换和导出，减少在多个工具之间切换带来的时间成本。

\subsection{形成可追溯的演示闭环}

系统面向管理端提供任务、日志、上传、转换和失败状态的可视化分析，使课程项目具备可演示、可解释、可追溯的实验闭环。系统不以静态 mock 数据冒充真实指标，而是以文件和任务接口的真实结果作为页面展示依据。

\subsection{落实数据安全与合规意识}

系统将网络安全、数据安全、个人信息保护等政策要求转化为设计约束，包括最小必要采集、用户文件可删除、预览缓存隔离、任务日志留痕和错误状态可解释等控制点\cite{cybersecuritylaw2016,datasecuritylaw2021,pipl2021}。同时，国务院关于促进大数据发展的政策文件也提示课程系统需要把数据采集、数据治理和数据分析形成闭环，而不是停留在单一业务页面展示\cite{bigdataaction2015}。

\section{研究现状}

\subsection{云盘产品现状}

Google Drive、Dropbox 等云盘产品通常将拖拽上传、文件夹块、类型图标和独立预览页作为基础体验\cite{googledrive,dropboxhelp}。对课程项目而言，最重要的不是复杂协同，而是让用户快速完成“上传资料、找到资料、预览资料、转换资料、导出资料”的闭环。

\subsection{文件转换工具现状}

Smallpdf、iLovePDF 和 Adobe Acrobat Online 等工具强调 PDF、Office、图片和文本之间的转换能力，但此类工具通常与课程项目云盘割裂。CulCloud 将转换任务与云盘文件、任务历史和结果下载关联起来，使转换结果能够回到文件管理流程中。

\subsection{PDF 办公编辑工具现状}

PDF 工具类产品通常具有 PDF 阅读器、页码跳转、缩放、文本高亮、画笔、图形、箭头、文本框、橡皮擦、打印和导出等能力。CulCloud 的 PDF Studio 以课程演示为目标，优先实现页面预览、轻量批注、页面整理和导出能力。

\section{主要工作内容}

本课题的核心工作在于攻克课程学习中产生的各类实验材料、课件文档及报告文件的管理杂乱难题，解决传统网盘、第三方转换服务与前端 PDF 在线编辑批注三者彼此割裂、用户体验脱节的缺陷。为此，CulCloud 平台设计了三大核心工作模块并实现其无缝咬合：文件云盘模块提供基础存储与目录层级映射；格式转换与预览模块将非标准格式文档静默投递至 Gotenberg 服务，为前端提供统一的 PDF 预览流；PDF 工作台与遥测大屏则在承接预览流的同时，支持用户在 Canvas 画布上进行富文本与线条批注，并将各阶段的操作日志与任务状态通过消息队列实时送往大数据分析大屏。通过各模块的紧密配合，实现从存储、转化、编辑到用户行为遥测的闭环处理。

\subsection{云盘与文件夹管理}

设计并实现云盘上传、文件夹管理、文件移动、类型分类、路径元数据、预览、下载、删除和重命名等功能，使“我的文件”模块具备接近真实云盘的基础操作能力。

\subsection{格式转换与预览能力}

构建格式转换中心，围绕 PDF、Word、Excel、CSV、Markdown、图片和文本等高频文件类型提供转换入口；同时为 PDF、图片、文本、Markdown、CSV、音视频和 Office 文件建立分层预览策略。

\subsection{PDF 编辑与大数据分析}

重构 PDF Studio，使其具备 PDF 页面预览、canvas 批注、页面整理、云端重排和打印导出；建立 Spark 遥测与管理驾驶舱，为上传、转换、下载、预览等行为提供数据分析依据。

\section{论文组织结构}

本文共分为七个章节展开论述，各章节的具体组织结构及核心内容安排如下：
第一章为绪论，阐述课题的研发背景、实际应用价值与技术研究现状，概述平台所涵盖的云盘、转换及分析三大模块的主要工作内容。
第二章为相关技术介绍，系统梳理项目开发过程中所采用的关键技术栈，重点分析前端 React 框架、后端 Node.js 服务、Gotenberg 高并发文档转换引擎以及用于离线遥测的 Spark 分析计算框架。
第三章为系统需求分析，从业务用例、功能需求和非功能性约束等维度切入，分析学生端文件操作和管理端遥测大屏的具体业务诉求。
第四章为总体设计，给出系统的微服务总体架构、数据库关系型表结构设计，以及各模块之间的通信与协作流程。
第五章为详细设计与实现，深入探讨云盘管理、Gotenberg 异步转换任务调度、PDF Studio 画布渲染与批注算法，以及 Spark 数据清洗与大屏聚合展示的编码实现细节。
第六章为系统测试，设计并执行功能覆盖测试、高负载压力测试与安全合规性审计，评估平台在并发转换和长周期运行下的鲁棒性。
第七章为总结与展望，归纳本课题已实现的系统功能与课程实践成果，反思 PDF 批注写回和 Office 预览转换中的不足，提出未来的技术优化路径。
