# Sprint 11 PRD v0.1 — LaTeX 正文均衡扩充与多智能体写作验收

Last Updated: 2026-06-22 16:50

## 背景

当前 LaTeX 报告已经完成 Word 模板封面对齐、7 章结构拆分和基础 LaTeX 门禁。`latex_chapter_audit.py` 显示正文已经具备完整骨架，但整体仍是扩写稿：7 章合计约 6500 个中文字符，距离课程报告期望的 10000--13000 个中文字符仍有明显差距。

本 Sprint 的目标不是让某一章堆出大量文字，而是让 7 个章节按照课程模板逻辑共同达标。扩写必须围绕真实系统、真实 PRD、真实测试和真实截图规划展开，避免出现单章膨胀、图表堆叠、AI 腔空话、Markdown 残留和编译警告瞒报。

## 总目标

将 LaTeX 报告正文扩充为可交付版本：

- 正文 7 章总中文字符数达到 10000--13000。
- 每章达到自身目标区间或有明确保留理由。
- 每章至少到 `section/subsection`，已拆出的三级标题不得空心化。
- 图表、截图、公式和测试表必须有前后解释，不允许连续堆图。
- 编译通过，并完成日志分级、封面视觉检查、静态扫描和计数验收。

## 章节扩充策略

### 第 1 章 绪论

目标是补齐选题动机与本文贡献。扩写重点包括课程资料管理痛点、云盘/文件转换/PDF 批注三类竞品启示、课程项目的工程价值和论文组织结构。第 1 章不需要堆大量图表，保持 1400--1800 字即可。

### 第 2 章 相关软件及技术简介

目标是让技术栈选择具有解释力。扩写重点包括 React/TypeScript/Vite、FastAPI、MinIO、Redis/Celery、LibreOffice/Gotenberg、PDF 渲染、Spark/ECharts 的作用边界，以及为什么这些技术适合办公与教学资料管理系统。避免泛泛介绍技术百科，必须回到 CulCloud 实际链路。

### 第 3 章 系统分析

目标是补齐系统开发前置分析。扩写重点包括用户角色、功能需求、非功能需求、可行性分析、安全合规和演示边界。可以加入用例表或角色需求矩阵，但表格后必须写分析结论。

### 第 4 章 系统总体设计

目标是让架构设计能够支撑实现章。扩写重点包括总体架构、用户端/管理端模块、对象存储路径、转换任务状态流、日志持久化、PM2 与 Docker Compose 的演示部署边界。后续可放架构图、数据流图和部署图，但每张图必须有图前引入与图后解释。

### 第 5 章 系统详细设计及实现

目标是成为全文实现核心章。扩写重点包括我的文件、文件夹移动、路径元数据、预览矩阵、转换中心、PDF Studio、管理驾驶舱和异常状态处理。该章预计承载最多截图，但不能只贴截图，必须按功能链路组织正文。

### 第 6 章 系统测试

目标是把白盒测试和演示验证写成可信证据。扩写重点包括测试环境、测试数据、云盘文件夹测试、预览矩阵测试、转换链路测试、PDF 工作台测试、历史记录/日志持久化测试和问题修复闭环。测试表格必须配测试结论。

### 第 7 章 总结与展望

目标是收束成果和边界。扩写重点包括已完成能力、课程实践价值、当前限制和后续演进。该章保持 900--1300 字，不承担技术细节堆叠。

## 多智能体协作模型

### 主智能体职责

主智能体负责质量验收和任务分发，不直接一次性重写全部章节：

- 读取 PRD、模板、计数器、LaTeX 门禁和当前章节。
- 将章节任务分发给章节子智能体。
- 统一术语、文件名、课程名、项目名和技术事实。
- 检查子智能体输出是否为结构化 LaTeX patch。
- 运行计数器、静态扫描和编译。
- 根据总字数和章节缺口决定是否返工。
- 记录残余风险和下一轮任务。

### 子智能体职责

子智能体按章节工作，每个子智能体只负责一个章节或一个强相关章节组：

- 章节 Agent A：第 1 章绪论与第 7 章总结。
- 章节 Agent B：第 2 章相关技术。
- 章节 Agent C：第 3 章系统分析。
- 章节 Agent D：第 4 章总体设计。
- 章节 Agent E：第 5 章详细实现。
- 章节 Agent F：第 6 章系统测试。

子智能体必须返回结构化 patch，不得返回散文式 Markdown。每个 patch 需要说明目标文件、锚点、操作类型、预计新增字数、事实来源和风险。

## 验收标准

- `python3 docs/02-process/scripts/latex_chapter_audit.py` 显示 7 章合计达到 10000--13000 中文字符。
- 单章未达目标时，必须由主智能体写明保留理由；不得用某一章过量文本掩盖其他章空心。
- `make -C docs/02-process/document/latex/cit-template/scripts clean compile` 通过。
- 日志扫描无 fatal、undefined reference、undefined citation、overfull hbox。
- 若有 underfull 或 rerun 类非阻断 warning，必须分级说明。
- 目标 `.tex` 无 Markdown 残留、无本地绝对路径泄漏、无 `\hline` 和竖线表格。
- 封面第一页渲染检查通过：logo 位置接近 Word 模板，封面无页眉。
- 输出 PDF 为 `docs/02-process/document/latex/cit-template/output/大数据与云计算课程大作业说明书.pdf`。
