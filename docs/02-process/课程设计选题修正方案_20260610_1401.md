# 课程设计选题修正方案

## 修正理解

**之前的错误**：想另起炉灶做一个"容器监控"系统，替换现有平台
**正确理解**：现有 CulCloud 云文件处理平台本身就是大数据系统，只需在上面增量

## 现有平台的大数据特征

| 特征 | 已有实现 | 大数据对应 |
|------|---------|-----------|
| 分布式存储 | MinIO S3（兼容 S3 API，支持水平扩展） | HDFS 替代方案 / 对象存储 |
| 分布式计算 | Gotenberg 转换引擎 + Redis 任务队列 | MapReduce-like 任务分发 |
| 数据流管道 | upload → store → queue → convert → result | ETL Pipeline |
| 任务调度 | Redis 任务状态管理 + FastAPI 异步 | 分布式任务调度 |
| 多种数据格式 | 15 种转换类型（PDF↔Word/Excel/PPTX/HTML/MD/SVG/PNG） | 多源异构数据处理 |
| 并发处理 | 100+ 并发请求支持 | 高吞吐批处理 |
| Web 服务 | FastAPI RESTful API | 统一数据服务接口 |

## 课程设计增量

## 数据来源（从现有平台提取）

平台已有数据，无需额外采集：

### 1. Redis 任务数据
```python
# 已有接口，直接可查
GET /api/v1/tasks/{task_id}
# 返回：task_id, status, result_url, error, timestamp

# 可遍历已存储的所有 task:* keys 获取历史任务数据
```

### 2. MinIO 对象元数据
```python
# 已有接口
GET /api/v1/files
# 返回：所有对象列表，含 filename, size, content_type, last_modified

# 可扩展：按文件类型、时间范围统计
```

### 3. MinIO 桶级统计
```python
# S3 API 可直接调用
minio_client.list_objects(bucket, recursive=True)
# 可计算：总对象数、总存储量、文件类型分布、日上传量趋势
```

## Spark 分析场景

| 分析场景 | 数据来源 | Spark 操作 | 可视化 |
|---------|---------|-----------|--------|
| 文件类型分布统计 | MinIO objects | 按 content_type 分组计数 | 饼图 |
| 存储趋势分析 | MinIO objects | 按日期分组，统计日增文件数和存储量 | 折线图 |
| 转换任务成功率 | Redis tasks | 按 status 分组，计算 success/fail 比例 | 饼图/卡片 |
| 热门转换类型 | Redis tasks | 按 conversion_type 分组计数 | 柱状图 |
| 大文件 TOP N | MinIO objects | 按 size 降序排列 | 排行榜/表格 |
| 任务吞吐量趋势 | Redis tasks | 按时间窗口统计任务完成数 | 折线图 |
| 用户上传行为分析 | MinIO objects | 按小时/日期统计上传活跃度 | 热力图 |
| 存储容量预警 | MinIO objects | 计算总存储占用、增长率预测 | 仪表盘 |

## Flask API 设计（新增端点）

## 部署方式

```yaml
# docker-compose.demo.yml 新增 profile
services:
  spark-analytics:
    image: python:3.8-slim + PySpark 3.x
    profiles: [analytics]
    
  flask-analytics:
    build: ./flask-analytics
    ports: ["5000:5000"]
    profiles: [analytics]
```

一键切换：
```bash
scripts/demo-up.sh core        # 现有平台
scripts/demo-up.sh analytics   # 现有 + 分析层
scripts/demo-up.sh all         # 全部
```
