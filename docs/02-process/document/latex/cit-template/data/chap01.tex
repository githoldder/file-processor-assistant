\chapter{绪论}

\section{课题背景}

随着课程资料、实验截图、数据集、报告文档和演示材料不断增长，学生在完成大数据与云计算课程项目时经常需要在本地文件、云端文件、格式转换工具和 PDF 标注工具之间反复切换。传统处理方式存在上传入口分散、文件分类不清晰、预览空间不足、PDF 办公编辑能力弱和实验数据难以追溯等问题。

CulCloud 平台面向课程大作业场景，将个人云盘、文件上传、格式转换、PDF 编辑室、任务监控和大数据分析驾驶舱整合到一个系统中。系统以真实 API 和任务数据为基础，避免静态 mock 指标误导用户；同时结合 Spark 遥测分析和前端可视化，为课程报告提供可验证的实验依据。

\section{研究意义}

本课题的意义主要体现在三个方面。第一，面向学生端提供可用的云盘与文件处理工作流，提高课程文档整理、转换和预览效率。第二，面向管理端提供任务、日志、上传、转换和失败状态的可视化分析，使系统具备可演示、可解释、可追溯的实验闭环。第三，将网络安全、数据安全、个人信息保护等政策要求转化为系统设计中的最小必要采集、可删除、日志留痕和风险提示等控制点。

\section{研究现状与竞品启示}

Google Drive、Dropbox、Box 等云盘产品通常将拖拽上传、文件夹块、类型图标和独立预览页作为基础体验。Smallpdf、iLovePDF 和 Adobe Acrobat Online 等 PDF 工具则强调阅读器、批注工具条、页面整理和导出的一体化工作台。对比这些竞品可以发现，CulCloud 的用户端不应默认展示缺少层次的文件列表，而应优先提供上传入口和块状分类；PDF Studio 也不应只停留在页面重排，而应覆盖画笔、图形、箭头、文本、高亮、橡皮擦和打印导出等办公编辑能力。

\section{主要工作内容}

本文围绕 CulCloud 平台完成以下工作：

\begin{enumerate}
  \item 设计个人首页真实数据展示机制，接入云盘文件、转换任务和失败任务接口；
  \item 实现云盘上传、文件夹管理、类型分类、文件预览、下载、删除和重命名；
  \item 构建格式转换中心，支持高频 Office、Markdown、图片与 PDF 转换链路；
  \item 重构 PDF Studio，使其具备 PDF 页面预览、canvas 批注、页面整理、云端重排和打印导出；
  \item 建立 Spark 遥测与管理驾驶舱，为上传、转换、下载、预览等行为提供数据分析依据；
  \item 整理政策合规、竞品调研、需求调研、算法公式、三线表、系统设计图、UML 图和参考文献。
\end{enumerate}

\section{论文组织结构}

全文共六章。第 1 章介绍课题背景、研究意义、竞品启示和主要工作。第 2 章介绍相关技术与竞品分析。第 3 章进行系统需求分析和总体设计。第 4 章说明系统关键模块实现。第 5 章给出测试方案与结果分析。第 6 章总结项目成果并提出后续改进方向。
