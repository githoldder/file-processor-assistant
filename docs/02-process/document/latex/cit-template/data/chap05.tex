\chapter{系统详细设计及实现}

本章说明 CulCloud 各核心模块的详细设计与实现，包括个人首页、我的文件、转换中心、文件预览、PDF 编辑室和管理驾驶舱。

\section{个人首页模块的实现}

\subsection{真实指标展示}

在个人首页中，为了向用户直观展示其存储空间占用和转换服务的使用状况，系统设计了基于后端真实数据的仪表盘组件。前端通过调用 \texttt{listFiles} 接口并传入参数 \texttt{\{recursive: true\}}，遍历用户在 MinIO 上的全部对象元数据，计算并统计文件总量与空间总体积；同时调用 \texttt{listTasks} 任务列表接口获取最近 24 小时内的成功转换任务与失败任务数量。为保障用户体验并避免在后台接口通信失败时展示可能引起歧义的零值，页面在请求 API 失败时将渲染明确的异常提示卡片，并向用户提供快速重试按钮，杜绝使用虚假的静态模拟数据。

\subsection{失败任务提示}

为了提供更细致的故障可解释性，系统从后端任务接口读取所有终态为失败（failed）的任务。当任务状态更新函数向 Redis 写入失败记录时，会将后端转换服务（如 Gotenberg）返回的详细错误原因（如文件损坏、格式不支持等）封装在任务对象的 error 字段中。前端操作面板与通知角标均直接读取该字段，使得用户不仅可以在首页侧边栏获知失败计数，还能在任务详情弹窗中直接查看其具体的错误堆栈，建立了“失败可回溯、原由可合理解释”的演示体验。

\section{我的文件模块的实现}

\subsection{上传与类型分类}

云盘模块是用户进行文档管理的首要入口。我的文件页面默认划分为拖拽上传热区和文件分类模块。用户可以通过拖拽操作将本地文件或文件夹直接释放在热区，或者使用“文件上传”和“文件夹创建”按钮提交数据。系统在接收到上传成功的响应后，会通过提取文件名的后缀扩展名，结合前端预设的白名单规则将文件归入 PDF、图片、文档、表格、演示文稿、音视频、压缩包以及其他类型中。这八种文件分类拥有独立的卡片展示和色彩级联指示器，方便用户在杂乱的课程资料中一键筛选目标格式。

\subsection{文件夹与路径元数据}

由于 MinIO 采用扁平的对象存储模型，文件夹并非物理实体，系统在设计上使用路径前缀和后缀为 \texttt{.keep} 的空对象来模拟目录的存在。为了让用户在多级目录结构中不易迷失，页面顶部设计了基于当前路径前缀（\texttt{currentPrefix}）的路径元数据导航面包屑，帮助用户清晰辨识当前处于根目录还是深层子目录下。为规避树形结构展示中的路径混乱，文件夹列表渲染时会自动执行前缀自检，过滤与自身前缀完全一致的递归节点，保障树级展开符合直觉。

\subsection{拖拽移动与移动到按钮}

在整理文件时，系统支持通过将文件节点拖拽至目标文件夹上方进行快速移动，或者点击节点操作列的“移动到”按钮，在弹出的目录树弹窗中选择目标路径。后端路由 \texttt{folders.py} 在处理移动请求时会严格进行“前缀包含性校验”：若用户试图将一个父文件夹移动至它自身的子目录或其自身内部，系统判定该操作将导致目录树形成死循环并产生孤立节点，从而直接返回 400 Bad Request 拒绝执行；若是合法移动，则对该文件夹下的所有子对象执行级联复制（CopyObject）至新路径前缀下，并批量删除旧前缀下的原对象。

\section{转换中心模块的实现}

\subsection{转换能力白名单}

转换中心是处理格式加工的核心。系统出于安全性、稳定性和用户体验一致性的考虑，仅在界面中向用户暴露通过严格本地验证的 9 种 P0 格式转换链路（包括 Word 到 PDF、Excel 到 PDF、CSV 到 PDF、Markdown 到 PDF、图片到 PDF、文本到 PDF 以及 PDF 拆分、旋转和合并等能力）。对于尚未通过 Gotenberg 完整验证的边缘格式，后端保留了调试路由，但用户端界面予以屏蔽，保证办公与教学资料处理流程的高可靠性。

\subsection{任务提交与状态轮询}

在用户选择转换源文件并确认转换格式后，前端调用异步接口将任务推入 Celery 队列。任务创建后，前端使用 React 组件内的定时器组件（基于 \texttt{setInterval}）启动 3--5 秒周期的延时短轮询。轮询接口不断提取 Redis 中的任务详情。若状态变更为完成（completed），前端会在页面历史列表中渲染带有 MinIO 临时签名的下载按钮，方便用户下载转换成果；若状态变更为失败（failed），前端清除定时器的同时，读取任务中的 \texttt{error} 信息并直接在对应的历史行中渲染醒目的警示提示。

\subsection{历史记录展示}

转换历史来自任务接口，而不是浏览器临时状态。成功、失败和处理中任务都应进入历史列表，使用户在刷新页面或重启前端服务后仍能查看已发生的转换操作。

\section{文件预览模块的实现}

\subsection{PDF 与图片预览}

PDF 使用浏览器内嵌预览或 PDF 页面渲染，图片使用自适应展示。预览页保留返回云盘、下载、预览类型、文件大小和大视口内容区域。

\subsection{文本、Markdown 与 CSV 预览}

TXT 使用纯文本展示，Markdown 渲染为 HTML，CSV 渲染为表格化 HTML。渲染结果需要进行安全隔离，避免将用户上传内容直接注入主页面。

\subsection{Office 与音视频预览}

Office 文件优先通过转换为 PDF 的方式预览。MP3、MP4 等音视频文件可通过浏览器原生 \texttt{audio} 和 \texttt{video} 控件预览，但此能力应定位为上传与预览扩展，不作为本次转换中心的核心链路。

\section{PDF 编辑室模块的实现}

\subsection{页面预览与缩略图}

PDF Studio 默认进入编辑室。用户可以上传本地 PDF 或从云盘选择 PDF。系统提取页面预览图后，底部缩略图用于选择页面、拖拽排序、旋转和删除页面。

\subsection{批注工具实现}

前端在页面图上叠加批注层，支持画笔、高亮、矩形、箭头、文本和橡皮擦。批注对象记录页面编号、坐标、颜色、线宽和文本内容，为后续写回 PDF 坐标提供数据基础。

\subsection{导出能力实现}

右侧导出面板提供云端页面重排导出和浏览器打印导出。页面重排由后端根据页面配置生成新 PDF，批注打印导出由浏览器打印渲染完成。

\section{管理驾驶舱模块的实现}

\subsection{遥测数据采集}

管理端通过上传、下载、转换、预览和失败事件形成遥测数据。事件数据进入后续分析流程，用于计算任务吞吐、失败率和文件类型分布。

\subsection{Spark 聚合分析}

Spark 对遥测数据按时间、动作和文件类型聚合，形成趋势指标、质量指标和异常指标。聚合结果以 CSV 或 API 形式提供给前端驾驶舱。

\subsection{可视化展示}

前端使用 ECharts 展示趋势、拓扑、桑基图和质量仪表盘，作为系统分析报告中的实验截图来源。

\section{本章小结}

本章围绕个人首页、我的文件、转换中心、文件预览、PDF 编辑室和管理驾驶舱说明了系统实现思路。系统实现的重点是让用户操作、后端接口、任务历史和报告证据保持一致。
