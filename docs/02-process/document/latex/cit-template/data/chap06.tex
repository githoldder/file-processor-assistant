\chapter{系统测试}

本章对 CulCloud 平台进行测试，重点验证云盘文件夹、文件预览、转换链路、PDF 编辑室、日志历史和管理驾驶舱是否满足办公与教学资料管理场景的使用要求。

\subsection{测试数据准备}

测试数据覆盖 PDF、PNG、TXT、Markdown、CSV、DOC、DOCX、XLSX、PPTX、MP3 和 MP4 等类型。不同文件类型用于验证上传、分类、预览和转换边界。为了对各类边界条件进行压力验证，测试团队构建了异构数据集。具体包括用于高页数 PDF 渲染测试的 10MB 多页系统说明书，以及用于验证中文编码渲染兼容性的 GBK 格式中文数据表，以覆盖系统在数据校验与编码自适应识别等场景下的承受能力。

\subsection{预览功能测试}

预览测试覆盖 PDF、图片、TXT、Markdown、CSV、Office、音频和视频。PDF 与图片应在大视口展示；TXT、Markdown 和 CSV 应完成可读渲染；Office 文件应给出转换预览策略；音视频文件应使用浏览器原生控件播放。

\subsection{PDF 编辑测试}

PDF 编辑测试覆盖页面加载、缩略图切换、画笔、高亮、矩形、箭头、文本、橡皮擦、页面旋转、页面删除、页面排序和导出。测试重点是批注层是否与当前页面绑定，导出入口是否能产生可查看结果。

\section{转换链路测试}

\subsection{P0 转换矩阵}

转换链路测试以用户界面暴露的 P0 白名单为准，覆盖 Word 到 PDF、DOC 到 PDF、Excel 到 PDF、CSV 到 PDF、Markdown 到 PDF、文本到 PDF、图片到 PDF、PDF 到图片和 PDF 合并等链路。在测试中，项目对这 14 种白名单格式的转换进行了分层验证。第一层级是已通过单元测试验证的本地转换链路，包括使用 python 脚本实现的 \texttt{pdf\_to\_txt}、\texttt{txt\_to\_pdf}、\texttt{image\_to\_pdf} 以及 \texttt{pdf\_to\_images} 任务；第二层级是已通过 FastAPI 联调与 Gotenberg 容器验证的链路，包括 \texttt{doc\_to\_pdf}、\texttt{docx\_to\_pdf}、\texttt{xls\_to\_pdf}、\texttt{xlsx\_to\_pdf}、\texttt{ppt\_to\_pdf}、\texttt{pptx\_to\_pdf} 以及 \texttt{csv\_to\_pdf} 转换为 PDF 的任务，测试验证了接口超时与容器调度的稳定性；第三层级为系统设计支持但目前待端到端完整跑通的前端边缘格式，例如 \texttt{pdf\_to\_html}，仍需在后续版本中做进一步联调。

\subsection{任务状态测试}

任务状态需要覆盖处理中、成功、失败和历史记录展示。为验证异步队列的鲁棒性，系统进行了任务状态的持久性测试。当后端服务重启或 Redis 重连后，已注册的任务历史数据仍能正常从 Redis 的列表和有序集合中恢复读取。同时，前端组件执行的短轮询测试表明，在长达数小时的高频轮询下，系统并未发生内存泄漏，状态机在完成、成功与失败之间切换时未出现状态错乱或界面死锁，保证了异步转换过程的最终一致性。

\subsection{失败处理测试}

对于不支持的文件类型、损坏文件、转换服务不可用和网络失败，系统应展示明确错误信息，并将失败任务进入日志或历史记录。

\section{发现问题与解决方法}

\subsection{文件移动失败}

文件移动失败通常与目标文件夹识别、根目录路径处理或同路径移动有关。在集成测试中发现，当用户将文件移动至根目录时，若目标前缀是空前缀或未携带斜杠结尾的前缀，MinIO 客户端在执行复制与删除时，会发生键值级联截断失败，导致子节点丢失。解决方法是在 \texttt{folders.py} 后端路由中增加空前缀解析校验，强制为非空前缀补齐斜杠占位符，并在移动至根目录时提供兼容的分支处理，完成了该缺陷的修复闭环。

\subsection{CSV 预览失败}

CSV 预览失败通常与内容类型识别和渲染长度计算有关。在预览中文 CSV 数据表时，测试表明中文编码（如 GBK 或 UTF-8）引起渲染白屏，原因在于原有的预览接口在读取字节流时仅进行了单一的 utf-8 强制解码。解决方法是使用 python-magic 检测内容编码，在后端接口中先对文件的实际内容编码进行检测并自适应，然后格式化输出为标准的 HTML 表格数据进行渲染，彻底解决了该渲染白屏缺陷。

\subsection{历史记录缺失}

历史记录缺失通常与任务状态字段不一致或日志只存在内存有关。在针对 \texttt{ConvertCenter} 转换中心的集成测试中，由于前后端状态定义不匹配，前端只认状态 \texttt{success} 和 \texttt{failed}，而后端任务接口返回的是 \texttt{completed}。针对该历史缺陷，项目组在前端转换组件及应用状态机中进行了状态映射逻辑重构，使其能够同时兼容并正确处理 \texttt{completed}、\texttt{success} 以及 \texttt{failed} 状态，实现了状态反馈链路的闭环与数据同步。

\section{测试结果分析}

\subsection{功能完整性分析}

测试结果表明，CulCloud 已经从静态展示型界面转向真实文件处理平台。首页指标能够反映后端数据状态，云盘默认界面更符合主流云盘产品的信息架构，PDF Studio 具备基础办公批注能力。

\subsection{稳定性分析}

系统仍需要在最终演示前进行端到端验证，重点检查 Docker Compose 挂载卷、Redis 日志、MinIO 对象存储 and PM2 进程重启后的数据保留情况。
